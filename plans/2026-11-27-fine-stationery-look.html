Fine Stationery: a theme and a Paper page

Design, 27 November 2026. Branch fine-stationery in H:\Source\repos\ThineCraft\ShareCraft-stationery, cut from main 2654a64. Source: the owner's proposal page sharecraft-fine-stationery-proposal.html (a Codex output, with light and dark palettes). Nothing below is built yet.

What the owner asked for. A look called "Fine Stationery": quiet, executive polish for a site, the library working exactly as it does now. The owner chose to take what fits ShareCraft's looks: the fonts, the colours and the paper-texture background. The deckled paper edge, the champagne-heavy decoration and the proposal's own layout are left out.

Approach chosen (A). A new built-in theme, "Fine Stationery", and a new look setting, Page: Plain or Paper, which any look may use. The fonts are the existing built-in Classic package. A site gets the full Fine Stationery look by choosing all three on Change the look.

1. Why, and what success looks like

  • A site owner can make a site feel like good letter paper rather than a filing cabinet: deep blue ink, serif headings, a warm, faintly textured page.
  • Success: choose the Fine Stationery theme, Classic fonts and Paper; the site's pages show it in light and dark mode, at 375 px wide and on a desktop, with every text and control as readable as today.
  • Anti-goals: no change to how the library behaves or is laid out; no raster image files; no text, control or scrolling list behind a filter; nothing that loosens the page's Content Security Policy; no page colour set from user input.

3. The Fine Stationery theme

Added to BUILT_IN_THEMES in crates/revisions/src/brand.rs as builtin:stationery, named "Fine Stationery", after Graphite. It gives its dark colours explicitly, taken from the proposal's dark palette, instead of deriving them.

ColourLightDark
Primary (links, buttons)#203c50, white button text#b4d5ed, dark ink button text
Secondary (header band)#172f40, white header text#182b3a, white header text

Checked with checkTheme in web/look.js: every check passes. BuiltInTheme gains optional primary_dark and secondary_dark (the other six stay derived), and theme() copies them, so the theme a site holds carries them like any custom theme. The brand-centre list, the theme picker, look cards and BUILDING's theme table pick it up from the same list. The JavaScript list of themes comes from the server, so no second copy is needed; look-vectors.json gains the theme as a case.

4. The Page setting: Plain or Paper

Stored and sent

  • A new field page on Look: an enum PageStyle { Plain, Paper }, serialised in snake case, #[serde(default, skip_serializing_if = "PageStyle::is_plain")]. Stored looks without it are Plain, so nothing existing changes and old files stay the same byte for byte.
  • Look input (PUT /api/sites/{id}/look, crates/server/src/looks.rs) takes an optional page; anything but plain or paper is refused as the menu style is.
  • The effective look (GET /api/sites/{id}/look) answers page: "plain" | "paper".
  • History, rollback, copying a site's look, templates (save, import, apply) and applying a whole look to many sites carry it as they carry menu. Applying only a brand theme and fonts to many sites leaves it alone.
  • Hubs (my call): Page goes with the site, as navigation and the menu style do, not with the hub's theme and fonts. Paper is a choice about the page, and a hub member keeps its own. Easy to move into the hub-lent part later if the owner wants that.

Shown

  • siteChrome in web/common.js sets data-page="paper" on <html> through setAttribute for a Paper look, and removes it otherwise. The value is checked to be exactly paper. The editor frame never takes it, so the editor stays neutral, as it does for colours.
  • web/style.css holds every Paper colour as fixed light-dark() values under html[data-page="paper"]. No colour comes from the look. It overrides the page tokens (--bg, --paper, --sheet, --text, --muted, --line) and adds a quiet champagne detail on the current navigation item and table row hover.
  • Grain: one html[data-page="paper"] body::before layer, position: fixed, inset: 0, pointer-events: none, behind the content, made of two faint repeating-linear-gradients as in the proposal. It is 26% opacity in light mode and 4% in dark. There is no SVG filter and no image, so the Content Security Policy is unchanged. It is painted once and does not scroll with the library.
  • Pages outside a site (Start, admin, brand centre) are unchanged.

Contrast. Text on paper is 13.95 (light) and 13.56 (dark); muted text 4.92 (light) and 8.94 (dark). The Paper page colours sit inside the range the theme checks already test (light between #f5f7f8 and #fff in luminance, dark no lighter than #202a2e), so every theme that passes today still passes on Paper. A unit test pins this. The light --bg value #f9f7f2 is my call; the builder may adjust it within that range.

Chosen

  • Change the look (web/site-look.html, web/site-look.js) gets a "Page" choice beside Navigation and Menu style: two radio cards, Plain ("ShareCraft's clean page") and Paper ("A warm page with a faint paper grain"), each with a small picture as the other cards have.
  • The live preview panels (preview-light, preview-dark) and the Paper card picture show Paper exactly as a live page does, grain included (my call). So the Paper rules in style.css match [data-page="paper"] on any element, not only <html>: the tokens are set on that element, and the grain is a ::before layer of it (of body when it is <html>, fixed; of the panel itself in the preview, absolute). The preview sets and clears the attribute on each panel as the draft changes.
  • The live preview panel shows Paper. The draft, lookInput, comparable and describeLookChange (web/look.js) carry page: history reads "Page: plain to paper".
  • The look studio's changed marks (look-studio.js) mark the Page part when it changes.

5. Fonts

No new font package. Built-in Classic already gives serif titles and headings (ui-serif, Georgia, 'Times New Roman', serif) and the system fonts for body and controls, which is what the proposal uses.

6. Out of scope

  • The deckled paper edge, the SVG grain filter, the proposal's app bar, hero gradient and table layout.
  • A one-click Fine Stationery card (approach C).
  • Paper on pages outside a site, and in the editor.
  • Letting brand-centre themes carry paper.

7. Checks before it is done

  1. Rust unit tests: the theme passes check_theme; page defaults to Plain, round-trips, is left out of the file when Plain, and an unknown value is refused.
  2. Server tests (targeted, as in brand_fonts.rs for the menu): put, effective look, history, copy and template carry page. The full suite runs on GitHub Actions only when the owner pushes.
  3. JavaScript tests (node --test): draft, lookInput, describeLookChange, the data-page attribute, and the Paper-contrast test.
  4. In the browser on the dev server: a site with Fine Stationery, Classic and Paper, light and dark, at 375 px and 1280 px wide. Library, a document page and Change the look show no clipped text and no horizontal scroll. Screenshots go to the owner.
  5. BUILDING.html: the built-in theme table gains Fine Stationery, and the look section describes page.
