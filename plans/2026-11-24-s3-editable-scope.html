Editable S3 storage

Proposal for the owner, 24 November 2026. Phase 1 (read-only) is on main at 78bfd6a. Nothing below is built yet.

What editable S3 involves

People add, replace, edit, rename and delete files in a library, and ShareCraft makes the same change in the bucket. Four pieces of work make that safe:

  • Never overwrite someone else's change. Every save names the version it started from. ShareCraft asks the bucket to accept the write only if the object is still that version. Cloudflare's documentation (checked today) says R2 does this check atomically, on a single upload and on finishing a large upload. If the object has changed, ShareCraft keeps both: your edit is saved beside the original as a named copy.
  • Never lose an accepted save. A save is kept in ShareCraft first, shown as "saving", checked by the virus scanner, and then written to the bucket by the background worker. A restart, going offline or a refused key keeps it queued. Editor saves are grouped, so the bucket gets at most one write per file every 30 seconds.
  • Moves and deletes are not atomic in S3. A rename is a copy and then a delete, once for every object. R2 has no object versioning, so a deleted file goes to a hidden .sharecraft-bin/ holding folder in the bucket for 93 days. That keeps the recycle bin and Restore working.
  • Modes and permissions. Each library is read-only or read and write. Before a library is switched to read and write, ShareCraft runs a short write probe, which leaves nothing in the bucket. A key that may only read is refused for read and write, in plain words. A refused write blocks the library ("read-only until fixed") and drops nothing.

Risks I can see now

  • Editor saves need the file session (file_room.rs, changed recently for G5) to save to a staged write instead of Git. If that takes more than a small change, the task stops and reports rather than reshaping the editors. Live co-authoring rooms are not touched.
  • Once a library is in read-and-write mode, deletes made in the bucket by others still show up as deletions in ShareCraft, exactly as now. Slice 1 adds no recycle-bin record for them.
  • The migration is number 0025 (main uses up to 0024).
  • The live R2 check uses a few hundred write requests, which is inside R2's free monthly allowance. I will re-read Cloudflare's price page and state the cost before asking for your yes.

A new work branch, s3-writes, cut from main 78bfd6a. It follows the same process as Phase 1: an implementer and a reviewer for each task, local targeted tests, and a full check.yml run after you approve a push. Nothing is merged or pushed without your go-ahead.
