S3 surfacing: demo script (Phase 1, read-only, Cloudflare R2)

Branch s3-surfacing, worktree H:\Source\repos\ThineCraft\ShareCraft-s3. About 15 minutes. You do every step that touches Cloudflare or types a key; Claude never sees the key.

Cost: R2's free tier covers this (1 million list and 10 million read operations a month, 10 GB stored, no download charge). The library polls the bucket on its check interval, so disconnect the demo library afterwards; the monthly request cap is not enforced yet (deferred Task 12).

Before the demo (once)

#StepWhere
1Create a bucket, for example sharecraft-demo.Cloudflare dashboard → R2 → Create bucket
2Upload a few files: Welcome.pdf, Reports/Q3 plan.docx, Reports/a b+c.txt (a space and a plus, to check key decoding), Photos/harbour.jpg. Create an empty folder Empty/.The bucket's Objects tab
3Create an API token with Object Read only, limited to that bucket. Keep the Access Key ID and Secret Access Key for step 7; do not paste them into chat.R2 → Manage R2 API tokens
4Note the S3 endpoint: https://<account id>.r2.cloudflarestorage.com (shown on the token page). Do not add :443.Same page

The demo

#StepWhat should happen
5Open the demo server Claude started (address in the hand-over) and sign in as the administrator.Home page
6Sharing settings → S3 storage → add an endpoint: name r2, address from step 4, region auto, addressing style path. Save.The endpoint is listed; the notes about approved addresses show below it
7On a site: New library → From S3 storage. Storage r2, bucket sharecraft-demo, folder empty, then the access key ID and secret from step 3. Create.The library opens with the banner "Listing the bucket…", then "Shows the files in S3 storage. Checked … ago."
8Browse: Reports, Photos, Empty.Folders and files match the bucket; Empty shows as an empty folder; a b+c.txt keeps its exact name
9Open Welcome.pdf, preview harbour.jpg, download a b+c.txt.Each opens; the first open takes a moment (fetched, scanned, cached), the second is instant
10In the R2 dashboard upload New.txt. Back in ShareCraft, Library settings → Source → Update now (or wait for the check interval).New.txt appears and opens
11Delete New.txt in R2, then Update now twice.It goes to the library's bin after one missed check (grace period)
12Try to rename or upload in the library.Refused: the library is read-only
13Library settings → Source: show "Access key ending …, secret set" and Replace key.The secret is never shown
14Sign in as the second (non-administrator) account in the other address (localhost vs 127.0.0.1), with view access to the library.Sees the files and "S3 storage", never the bucket, endpoint or key

After the demo

#Step
15Library settings → Source → Disconnect ("Nothing in the bucket is changed"). The polling stops.
16Optionally delete the API token and the bucket in the R2 dashboard.
