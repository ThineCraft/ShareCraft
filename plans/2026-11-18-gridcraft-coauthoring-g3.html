GridCraft live co-authoring, plan G3: identities, explicit commands, the apply loop and per-person undo: implementation plan

ShareCraft · Stage 2, GridCraft editor track · Written 18 November 2026 · Base sharecraft at 097d1514 · Branch coauthor-g3

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development or superpowers:executing-plans. Steps are checkboxes. Read the binding spec and the G1 proof report before starting. One task id per commit; do not put AI or agent attribution in a commit or pull request.

Goal: make the first GridCraft commands safe to put into ShareCraft's one ordered live log. A command names sheets, rows and columns by session identity rather than by whatever position they occupy now; every shared command carries all of its targets; the G2 client can copy, restore, apply and re-run a GridCraft document; and Undo sends a guarded reverse of this person's last action without removing another person's later work.

Architecture:

  • gridcraft-engine::coauthor is the fork-owned adapter. It owns a normal Session, a session-only identity table, and the personal undo history, and implements G2's collab_live::client::LiveEditor. The existing engine stays the sole executor of workbook changes.
  • A canonical gridcraft/1 JSON payload is produced before LiveClient::local. It contains one allow-listed command, identity targets, formula references by identity, and the origin year used for a date typed without a year. The receiving adapter resolves identities to current positions and calls Session::execute with the existing explicit command form.
  • GridSnapshot copies only agreed document state: workbook, calculation state (including RAND), revision, and identities. It deliberately excludes a person's active sheet, selection and personal history. Applying a received command captures and restores that view by sheet identity.
  • GridCoauthor composes LiveClient<GridLiveEditor> with personal-history bookkeeping. G3 drives it only through an in-process simulated server. G5 will connect the same object to sockets and the screen.
  • Undo records field-level before/after guards while the original command is first shown. Undo and Redo serialize those guards as ordinary gridcraft/1 entries. A guard restores only a field that is still equal to the value this person's action left there.

Tech stack: Rust 2024 and the existing GridCraft workspace; G2's Rust collab-live crate through a sibling path dependency; existing serde, serde_json, thiserror, sha2, formula AST and engine/model/calc crates. No new third-party dependency. All dependencies remain within the repository's MIT/Apache/BSD/ISC licence allowlist.

Proposals for the owner

The binding spec fixes the behaviour. The following names, limits and boundary choices are not fixed there; this plan proposes them explicitly.

  1. Use G2 directly. Add collab-live = { path = "../../../ShareCraft/crates/collab-live" } to crates/engine/Cargo.toml, rather than copying its trait. This tests the real apply loop and OrderedIds that G5 will use. The implementation PR records the tested ShareCraft commit; both sibling checkouts are required to build this branch.
  2. Format name and module names. The first payload format is gridcraft/1. Fork code lives in crates/engine/src/coauthor/; its public façade is GridCoauthor, and its LiveEditor implementation is GridLiveEditor.
  3. Identity shape. WorkbookIds.sheets is an OrderedIds; each live sheet identity owns OrderedIds::base(MAX_ROWS) and OrderedIds::base(MAX_COLS). Thus every initial sheet, row and column is participant 0 plus its zero-based base position; inserted items use LiveClient::new_ids. A cell is CellId { sheet, row, col }.
  4. Filter names. Keep the UI toggle data.filter local-only. Add idempotent data.filterSet {sheet, range} and data.filterRemove {sheet, range}. Extend existing data.filterBy, data.clearFilter (criteria only) and data.reapply with explicit sheet and range.
  5. Large-workbook rule. LARGE_WORKBOOK_CELLS is 100,000 stored cells across the workbook. Row, column or sheet structure commands at or above it use Mode::WaitForServer; all other G3 commands use ShowAtOnce. G3 does not ship a cheaper structural re-run. It may be added later only with the same straight-through equality test and a heavier-formula timing win.
  6. View fallback after deletion. A remote command preserves the local active sheet by LiveId. If that sheet was deleted, use the next surviving sheet at the deleted position, else the preceding sheet, and use that sheet's remembered selection (or A1). No remote command chooses an unrelated sheet merely because it became active while executing.
  7. Clock and dates. An agreed entry uses Stamp.at_ms through gridcraft_core::date::serial_from_unix_ms for NOW/TODAY and Stamp.seed for RAND. A cell.set payload also carries origin_year: i32; year-less date parsing uses it. A locally shown volatile formula sets Outcome.read_stamp = true, so G2 re-applies it after the server stamp arrives.
  8. Agreement means entered content. GridLiveEditor::agreement_digest() returns only fingerprint(...).entered. The computed digest stays a diagnostic in native-only tests and is never used for cross-platform room agreement until both builds share a maths library.
  9. Personal history budget. Keep at most 100 actions or 128 MiB per person, using the same visible limits as current local history but with content-based accounting. Evicting an old personal action affects only that person's available Undo; it cannot affect convergence and no peer assumes the same depth.
  10. Large undo payloads. G3 has no G4 side-channel for large content. If a guarded reverse exceeds G2's MAX_PAYLOAD_BYTES, Undo is refused with “This change is too large to undo while sharing”; the original change remains. Ordinary row/column edits and the regression fixtures must fit.
  11. G3 stops below the UI. GridCoauthor::submit, undo, redo, receive, tick and base_ready are the stable host surface. G5 replaces direct edit.undo/edit.redo dispatch and the UI's direct history trimming; G3 tests the surface in-process and does not add sockets or browser code.

Not in this plan

  • No WebSocket, browser host bridge, frame-page notice UI, presence drawing, read-only UI or real-browser test. Those are G5.
  • No checkpoint upload/load, second-writer hash, row-height checkpoint fix, returning-client major versions, large-content side channel, unsaved-log limit or server fingerprint exchange. Those are G4.
  • No personal filter views. C10 makes the G3 filter shared.
  • No live keystrokes inside a cell. A cell draft stays private until Enter (Q2).
  • No shared macros, scripts, Solver, data import, AutoFit column width, password changes, random-number tool, pictures, objects, sort, cut/move, insert/delete cells with shift, or large paste. They remain refused until separately made deterministic and target-explicit.
  • No shared object-number allocation and no identity written into XLSX. Session identities die with retained room data (C7).
  • No common desktop/browser maths library. Until it exists, agreement is entered content only and desktop joining remains subject to C16.

Global constraints

  • Branch coauthor-g3 is based on sharecraft at 097d1514. Main changes only through a pull request.
  • No panic, unwrap, expect, panic!, unreachable!, todo!, unimplemented! or unsafe in non-test code. Input sizes, identity counts, indexes and allocations are hostile and bounded.
  • Every user-visible edit remains an engine command. The co-author adapter translates identities and invokes Session::execute; it does not edit a Workbook behind the engine except when restoring a previously captured snapshot.
  • Only the allow-listed G3 commands enter the live log. Missing targets, unknown payload keys, unknown identities, invalid formula-reference counts and payloads over G2's limit are refused without changing document or identity state.
  • A command that cannot resolve a deleted target returns Effect::NoEffect { reason }. It never guesses a nearby position. A later same-cell entry wins because entries execute in log order.
  • View state and personal history are not shared, not fingerprinted and not serialized into a shared entry. A checkpoint later writes the stored workbook view, per C11.
  • Use checked/saturating arithmetic and the existing MAX_ROWS/MAX_COLS. Identity operations must be atomic: an error leaves OrderedIds and the workbook unchanged.
  • No new third-party dependency. Check any dependency change against the licence allowlist. No vendor artwork, strings, screenshots, fonts, templates or sample files.
  • Do not change CI. Keep WASM building. Finish with cargo xtask ci; report exactly what ran.
  • Update docs/coauthor-determinism.md, the selection-reader fixture and affected roadmap/gap documents when implementation lands. Do not hand-edit generated parity files; run their generator if catalog metadata changes.

G3 shared command surface

The wire does not send arbitrary {id, params}. SharedCommand has typed variants. The adapter resolves the identity form into the engine form below. “Required” means required in a live payload even if the ordinary single-user command still has a selection-based default.
