Accounts and Permissions Implementation Plan

ShareCraft · Stage 1, part 2 of 3 · Written 10 November 2026

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps are checkbox items. Do not tick them in this file; the execution ledger is the record.

Goal: people sign in with their own account, a document can be opened only by the people it is shared with, someone whose access is removed is put out of a live session at once, and every saved revision and every access change is recorded in PostgreSQL.

Architecture: a new records crate owns PostgreSQL: accounts, sign-in sessions, documents, access grants, the revision index and the event log. The server signs people in with a cookie, checks the cookie and the person's role when a WebSocket opens, and keeps each connection's account and role in the document's room. Access changes are written to PostgreSQL first and then sent to the open room as a command, so the room removes or demotes the person without anyone reconnecting. Git stays the record of content; the PostgreSQL revision index is derived from Git and can be rebuilt from it.

Tech stack (added): sqlx (PostgreSQL, tokio runtime, no TLS feature, no compile-time query macros), argon2, sha2, getrandom, time, rpassword, dotenvy, reqwest (tests only, default features off). Add each with cargo add at its current stable release with the fewest features that work. PostgreSQL 18 is installed locally on port 5433.

Spec: scope.html (D09, D14–D18, SC-11, SC-21, A04, A07, A13) and sequencing.html (Stage 1, spine rules S2, S4, S5, S7). Read both, and BUILDING.html, before starting.

Global constraints

  • Rust only for server code (D14). Page scripts call the API and wire the WebAssembly client; they hold no merging or permission logic.
  • Licence MIT OR Apache-2.0 on every crate (D17). No copyleft dependencies (GPL, LGPL, AGPL, MPL). Task 1 adds a check that enforces this; if a dependency this plan names fails it, stop and report instead of adding an exception.
  • One organization per installation (D18): no organization or tenant identifiers in tables, types, paths or messages.
  • Secrets: never print, log, commit or put in a report the contents of .env, a database URL, a password, a password hash or a session token. Refer to them by variable name. Do not edit .env. Types holding them must not show them through Debug or Display.
  • SQL is written with bind parameters only. The one exception is the generated schema name in the test helper, which is hexadecimal it produced itself.
  • Authorization at every boundary (SC-11): every /api route and the WebSocket route identify the caller through the one Signed extractor, and decide access through Db::role. No handler reads the cookie or the grants table on its own.
  • A person with no access to a document gets the same answer as for a document that does not exist: 404.
  • Events never contain document text, passwords or tokens.
  • Git stays the only store of content and RevisionStore::checkpoint the only code that writes it (S3). PostgreSQL holds an index of revisions, never the content.
  • The server keeps listening on loopback addresses only, and the Host and Origin checks stay. Do not add a way to bind elsewhere.
  • collab-core, collab-text, protocol and web-client must still build for wasm32-unknown-unknown and must not depend on records, sqlx or tokio.
  • Workspace lints apply to all non-test code: no unsafe, unwrap, expect, panic! or indexing that can panic. Input from a client or a database row must never stop the server.
  • Tests use the real PostgreSQL named by TEST_DATABASE_URL, each in its own schema. A test that needs the database and finds the variable unset fails with a message saying so; it is never skipped.
  • Work on branch stage-1-accounts. Run cargo xtask check before each commit. Commit after each task with the message given. Do not push.

Review focus

Conditions the scope implies that are most likely to hurt a real person. Each has a test in the task named.

  1. Access removed while the person is connected or connecting. They must be out within a second, their open tab must stop showing the text, a change they send afterwards must not be committed, and a join that was already under way must not slip through. The same person in a second tab or a second sign-in is handled too. Task 7 (revoked_editor_is_removed_within_one_second, access_ended_during_join_is_caught, sign_out_closes_that_sessions_sockets_only).
  2. Guessing passwords and cross-site requests. A wrong password and an unknown email get the same answer; repeated failures are refused; another website open in the same browser cannot sign out, share or open a socket. Task 4 (wrong_password_and_unknown_email_look_the_same, sixth_failed_attempt_is_refused, cross_origin_post_is_refused).
  3. Git and PostgreSQL disagree. The server stops between writing a commit and recording it, or the record cannot be written. The save must still count as saved and the index must catch up without duplicates. Task 8 (index_failure_does_not_fail_the_save, reconcile_at_start_reads_revisions_written_while_stopped, rebuild_reproduces_live_records).
  4. Awkward names and emails. A display name with <, control characters or only punctuation, a 300-character email, two emails differing only in case. None may break saving, credit the wrong person or run as markup in a page. Task 2 (hostile_names_and_emails_are_refused, email_is_unique_ignoring_case) and Task 10 (names are written with textContent).
  5. Someone else changed the document underneath a session. A checkpoint refused as stale must tell the people in the room once, stop accepting changes and never overwrite the other revision or retry forever. Task 8 (stale_checkpoint_stops_the_room_with_a_conflict).

    pub async fn users(&self) -> Result<Vec<User>, DbError>;                      // by email
    pub async fn set_disabled(&self, actor: UserId, id: UserId, disabled: bool) -> Result<(), AccountError>;
    pub async fn sign_in(&self, email: &str, password: &str) -> Result<(Session, SessionToken), SignInError>;
    pub async fn session(&self, token: &SessionToken) -> Result<Option<Session>, DbError>;
    pub async fn end_session(&self, id: SessionId) -> Result<(), DbError>;
    pub async fn events_about(&self, subject: UserId) -> Result<Vec<Event>, DbError>; // oldest first

pub struct Event { pub id: i64, pub at: OffsetDateTime, pub kind: String, pub actor: Option<UserId>,
                   pub subject: Option<UserId>, pub document: Option<DocId>, pub detail: serde_json::Value }

Rules:

  • Email: trimmed; one @ with text on both sides; no whitespace or control characters; at most 254 characters; unique ignoring case.
  • Name: trimmed; 1 to 60 characters; no control characters, < or >; at least one letter or digit.
  • Password: 10 to 256 characters. Stored as an Argon2id hash in PHC string form with the crate's default parameters. Hashing and verifying run in spawn_blocking.
  • sign_in verifies against a fixed dummy hash when the email is unknown, so both cases take the same work.
  • A session row stores the SHA-256 of the token, never the token. session returns None for an unknown, ended or expired session and for a disabled account.
  • set_disabled(true) ends all of that account's sessions in the same transaction and refuses to disable the last enabled administrator (LastAdmin).
  • Each change writes its event in the same transaction: user.created, user.disabled, user.enabled, session.started, session.ended, and sign_in.failed (only for an email that belongs to an account, with that account as subject).

pub struct Document { pub id: DocId, pub name: String, pub created_by: Option<UserId>,
                      pub revision: Option<String>, pub revised_at: Option<OffsetDateTime> }

pub enum AccessError { NotFound, NoSuchUser, Forbidden, LastOwner, InvalidName, Exists, Db(DbError) }

impl Db {
    pub async fn create_document(&self, actor: UserId, id: DocId, name: &str) -> Result<Document, AccessError>;
    pub async fn document(&self, id: DocId) -> Result<Option<Document>, DbError>;
    pub async fn role(&self, user: UserId, doc: DocId) -> Result<Option<Role>, DbError>;
    pub async fn documents_for(&self, user: UserId) -> Result<Vec<(Document, Role)>, DbError>;  // newest first
    pub async fn grants(&self, actor: UserId, doc: DocId) -> Result<Vec<Grant>, AccessError>;
    // role None removes the grant. Returns the person's role before and after, as Db::role would report it.
    pub async fn set_access(&self, actor: UserId, doc: DocId, user: UserId, role: Option<Role>)
        -> Result<(Option<Role>, Option<Role>), AccessError>;

}

Rules:

  • role is the single access decision: None for a disabled or unknown account or a document that does not exist; Owner for an enabled administrator on every document; otherwise the grant, if any.
  • The creator is granted Owner in the same transaction. Name: trimmed, 1 to 120 characters, no /, \ or control characters.
  • grants and set_access need the actor's role to be Owner: NotFound if the actor has no role on the document, Forbidden if it is lower.
  • set_access locks the document's grants, and refuses a change that would leave no Owner grant (LastOwner). Setting the role a person already has changes nothing and records nothing.
  • Events in the same transaction: document.created, access.granted, access.changed, access.revoked, with actor, subject, document and {"role": …} or {"from": …, "to": …}.

Rules:

  • history lists the commits reachable from the document's reference whose tree under docs/<doc> differs from their parent's. Authors are the commit author followed by its Co-authored-by trailers; an author's id is the part of the email before @.
