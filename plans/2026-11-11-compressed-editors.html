Serve the editors compressed: implementation plan

ShareCraft · after Stage 1 · Written 11 November 2026

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development or superpowers:executing-plans. Steps are checkboxes.

Goal: a browser downloads each editor compressed, not raw: SolidCraft's 153 MB WebAssembly file arrives as about 48 MB (gzip) or less (Brotli), and the other editors shrink by about two thirds. No change to any editor fork, and no slower editor.

Approach: compress once, when an editor is installed: cargo xtask editors build writes a Brotli copy (.br) and a gzip copy (.gz) beside each compressible file. The server's static file service (tower-http ServeDir) is told to serve those copies, with Content-Encoding and Vary: Accept-Encoding, to browsers that accept them, and the plain file otherwise. Nothing is compressed per request. A new cargo xtask editors compress adds the copies to editors already installed, so no rebuild is needed.

Owner decision: 11 November 2026, after the SolidCraft size experiment showed size-oriented compiler settings make SolidCraft about twice as slow: keep today's builds and serve them compressed.

Global constraints

  • New dependencies only with permissive licences (MIT, Apache-2.0, BSD, zlib); no copyleft (D17). Preferred: flate2 (MIT/Apache) and brotli (BSD-3-Clause/MIT), in xtask only; the server needs none (ServeDir reads the copies).
  • The editor guard stays exactly as it is: sign-in, same origin, installed editor, path inside its folder, the editor's security policy, no-cache, nosniff. Compressed answers carry the same headers.
  • The compressed copies always match the file beside them: written from it at install, in the same step, never edited by hand.
  • editors verify and the editor manifest keep working; the copies are not listed as editor files of their own.
  • Never print .env, database addresses or passwords.

Review focus

  1. A browser that sends no Accept-Encoding (or only identity) still gets the plain file, byte for byte.
  2. An editor installed before this change (no copies) is served exactly as before.
  3. A request for file.wasm.br or file.wasm.gz by name never leaks anything outside the editor folder.
  4. The Content-Type of a compressed answer is the original file's type (application/wasm must stay, or the browser's streaming compile fails).
  5. Range requests and revalidation (If-None-Match, If-Modified-Since) still answer correctly with compression on.

Task 1: precompressed copies at install, and a compress command

Files: xtask/src/editors.rs, xtask/src/main.rs (new subcommand), xtask/Cargo.toml.

  1. Write failing tests: install_writes_compressed_copies (a built folder with a.wasm, b.js, c.css, index.html, d.png and a 100-byte e.js: after install, .br and .gz exist beside a.wasm, b.js, c.css and index.html, none beside d.png or the tiny e.js, and each copy decompresses to its file's bytes); compress_adds_copies_to_an_installed_editor; compress_replaces_stale_copies; verify_ignores_compressed_copies.
  2. Implement fn write_compressed_copies(dir: &Path) -> Result<()>: for files with extension wasm, js, mjs, css, html, json, svg, txt or webmanifest and at least 1024 bytes, write <name>.br (Brotli; quality 11 below 20 MB, a lower quality above to keep install time reasonable; report the measured time) and <name>.gz (gzip level 9), each to a temporary name and then renamed. Remove copies whose source file no longer exists. Call it at the end of install.
  3. Add cargo xtask editors compress [id]: runs it for one or all installed editors and prints sizes before and after.
  4. Run the xtask tests; commit feat(xtask): write compressed copies of editor files at install.

Task 2: the server serves the copies

Files: crates/server/src/editors.rs and the tests that already exercise the editor route with a temporary editors folder.

  1. Write failing tests: editor_files_are_served_brotli_when_accepted (Accept-Encoding "br, gzip": Content-Encoding br, body equals the .br copy, Content-Type application/wasm, Vary includes Accept-Encoding, and the editor policy, no-cache and nosniff present); editor_files_fall_back_to_gzip; editor_files_are_plain_without_accept_encoding; editor_without_copies_is_served_plain.
  2. Implement: ServeDir::new(..).precompressed_br().precompressed_gzip().
  3. Run cargo xtask check; commit feat(server): serve editors' compressed copies.

Task 3 (controller): compress the installed editors, check in the browser, documents

  1. cargo xtask editors compress; record before and after sizes for all four editors; restart the server.
  2. In the browser: open one document per editor; confirm the wasm arrived with Content-Encoding: br and its transferred size; edit, save and reload once per editor.
  3. BUILDING.html (sections 13 and 18: drop "No compression"; describe the copies and the compress command) and editors.html (section 02: the measured compressed download sizes), with colour banding on any new table. Commit docs: editors are served compressed.
