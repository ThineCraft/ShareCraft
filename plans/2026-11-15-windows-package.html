A ready-to-run Windows package: implementation plan

ShareCraft · tooling · Written 15 November 2026

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development or superpowers:executing-plans. Steps are checkboxes.

Goal: the owner copies one folder (or one zip) to another Windows 11 machine and double-clicks Install ShareCraft.cmd. A few minutes later ShareCraft is running in the browser with an administrator account, a malware scanner stand-in, and its own database. The other machine needs no compiler, no Git and no separately installed PostgreSQL, and nothing asks for administrator rights.

Architecture:

  • Everything prebuilt: the package holds a release build of sharecraft-server.exe and xtask.exe (for the stand-in scanner), the web/ pages with web/pkg built, and the four built editors.
  • Its own PostgreSQL: the package also carries a private copy of PostgreSQL 18 (only bin, lib and share). It comes from this machine's installation, so nothing is downloaded; the PostgreSQL licence allows this.
  • Installing, without administrator rights: a PowerShell script, run through a .cmd wrapper, copies the program into %LOCALAPPDATA%\Programs\ShareCraft and makes a database cluster under %LOCALAPPDATA%\ShareCraft\db on a free local port. It writes .env with a random password that is never shown, creates the first administrator (asking for the email, name and password), and adds Start-menu shortcuts.
  • Starting and stopping: Start starts PostgreSQL, the stand-in scanner and the server, then opens the browser. Stop shuts them down.
  • No Git needed: the server writes its Git repositories itself through the gix library, so Git is never called.

Tech stack: the existing workspace (release build), PowerShell 5.1 (built into Windows 11), and this machine's PostgreSQL 18 binaries. No new dependency.

Spec: the owner's request of 15 November 2026: "not to compile the app, just to install it and have it up and running", including Git and PostgreSQL if possible. Standing rule: Windows features must not need per-machine administrator work. Security rules: never print .env, database addresses or passwords.

Proposals in this plan for the owner to check

  1. Per-user, no administrator rights: the package installs for the signed-in Windows user only, and does not register a Windows service. ShareCraft runs while the user's Start shortcut has it running, and an optional "Start when I sign in" choice adds a Startup shortcut.
  2. The stand-in scanner (fake-icap) is set up and switched on, so malware scanning can be tried at once. The guide explains how to point it at a real ClamAV scanner later.
  3. Still local only: ShareCraft keeps answering only on the machine itself (http://127.0.0.1:<port>), as today. Reaching it from other devices needs the production mode that is not built yet.
  4. Built from the plan 3C branch once its final fixes pass, so the package has every feature to try. A new package can be made at any time with one command.

Not in this plan

  • A signed .msi/.exe installer, automatic updates, a Windows service, HTTPS, access from other devices, and Linux or macOS packages.

Global constraints

  • Package layout:
    • Folder: ShareCraft-<version>-windows/.
    • Scripts: Install ShareCraft.cmd, scripts\install.ps1, scripts\start.ps1, scripts\stop.ps1 and scripts\uninstall.ps1.
    • Program files: bin\sharecraft-server.exe and bin\xtask.exe; web\; editors\ (with their .br/.gz copies).
    • Database files: pgsql\bin, pgsql\lib and pgsql\share.
    • Documents: README.html (the guide), LICENCES.html, and VERSION (the commit id and build date).
    • Zipped as ShareCraft-<version>-windows.zip.
  • Made by cargo xtask package [--out DIR]. It builds release binaries into CARGO_TARGET_DIR and runs cargo xtask web. It copies the editors only if cargo xtask editors reports them installed and matching editors.toml; otherwise it refuses and says why. PostgreSQL is copied from SHARECRAFT_PG_DIR, or from C:\Program Files\PostgreSQL\18 if that is not set; pgAdmin, documentation, symbols and the installer's own files are left out. It writes the zip and prints its path and size. It never copies .env, data\ or any test file.
  • Installing (install.ps1, PowerShell 5.1, StrictMode, every step's exit code checked, stopping with a plain message on any failure):
    1. It refuses if ShareCraft is already installed for this user, unless -Reinstall is given; a reinstall keeps the data and database.
    2. It copies the program to %LOCALAPPDATA%\Programs\ShareCraft.
    3. It picks the first free port from 5440 to 5460 for PostgreSQL, and from 8787 to 8799 for ShareCraft.
    4. initdb makes the cluster under %LOCALAPPDATA%\ShareCraft\db with --auth=scram-sha-256 --encoding=UTF8 --locale=C, a random 32-character superuser password passed through --pwfile (a temporary file deleted at once), listening on 127.0.0.1 only.
    5. It creates a database role sharecraft with its own random password, and a database sharecraft.
    6. It writes %LOCALAPPDATA%\ShareCraft\.env holding DATABASE_URL, readable only by this user (the file's access list narrowed with icacls to the current user).
    7. It writes %LOCALAPPDATA%\ShareCraft\settings.cmd, setting SHARECRAFT_ADDR, SHARECRAFT_DATA (%LOCALAPPDATA%\ShareCraft\data), SHARECRAFT_WEB and SHARECRAFT_EDITORS_DIR.
    8. It runs sharecraft-server add-user --admin. The email and name are asked by the script; the password is asked by the server itself, never on a command line.
    9. It starts everything once and sets the scanner address to the stand-in scanner through the server's settings route, signed in as the new administrator.
    10. It adds Start-menu shortcuts: "ShareCraft" (start and open), "Stop ShareCraft", and "Uninstall ShareCraft".
    11. It opens the browser.
    No step needs administrator rights. Passwords, the database address and .env are never printed or logged.
  • Start:
    • It starts PostgreSQL with pg_ctl start -w, if it is not already running.
    • It starts the stand-in scanner and the server hidden, with their output going to %LOCALAPPDATA%\ShareCraft\logs\.
    • It waits until the server answers, then opens the browser. If it is already running, it only opens the browser.
    Stop:
    • It stops the server and the scanner by the process ids it recorded.
    • It then stops PostgreSQL with pg_ctl stop -m fast.
  • Uninstall: it stops everything, then asks "Also delete all ShareCraft data and the database?" (default No) and removes only what was confirmed, plus the program and the shortcuts. Nothing is deleted without that confirmation.
  • The guide (README.html, plain English, banded tables in light and dark):
    • What it is; what you need (Windows 11 and about 2 GB free).
    • How to install, sign in, start and stop.
    • Where the data lives, and how to back it up (stop, then copy %LOCALAPPDATA%\ShareCraft).
    • How to point the scanner at ClamAV.
    • That the computer's own antivirus may remove test files.
    • Limits (this machine only; no HTTPS) and how to uninstall.

Review focus

  1. No secret leaks: no password or database address appears in the console, the logs, a command line visible in the process list, or the package itself. (Task 2: the script passes secrets through files that only this user can read, then deletes them, and a test inspects the package for .env or data.)
  2. A second Install, or a port already in use, never overwrites an existing database or data folder. (Task 2, -Reinstall.)
  3. Folder names with spaces or non-ASCII characters (for example C:\Users\Zoë Smith) work throughout. (Task 2 quotes every path; Task 3 checks it.)

Task 1: cargo xtask package

Files: create xtask/src/package.rs; modify xtask/src/main.rs; add the scripts and README.html under packaging/windows/ (Task 2 writes them; this task copies them in).

  1. Write unit tests for the file-selection rules: PostgreSQL files kept and dropped; .env, data and target never copied; refusal when editors are missing or stale. Run them: they fail. Implement. Run cargo xtask check: it passes.
  2. Commit feat(xtask): package a ready-to-run Windows build.

Task 2: the install, start, stop and uninstall scripts, and the guide

Files: create packaging/windows/Install ShareCraft.cmd, packaging/windows/scripts/{install,start,stop,uninstall,common}.ps1, packaging/windows/README.html and packaging/windows/tests/scripts.Tests.ps1.

  1. Write Pester-free PowerShell self-tests, run by powershell -File tests\scripts.Tests.ps1:
    • Port picking skips a port that is in use.
    • Paths with spaces and non-ASCII characters are quoted.
    • .env is written with a narrowed access list.
    • Secrets never reach the console: output is captured and searched.
    • A reinstall keeps the data.
    Run them: they fail. Implement. Run them: they pass.
  2. Commit feat(packaging): Windows install, start, stop and uninstall scripts and guide.

Task 3 (controller): make the package and try it

  1. Run cargo xtask package from the plan 3C branch head.
  2. Install into a temporary Windows user profile folder, using a %LOCALAPPDATA% override pointing at a path that has a space and an accented letter.
  3. Run Start, sign in, upload a file and see it scanned, then run Stop, then Uninstall and keep the data. Record each step as checked or not, and give the owner the zip's path and size.
