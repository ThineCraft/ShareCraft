Stage 1 Follow-ups: Implementation Plan

ShareCraft · after Stage 1 · Written 10 November 2026

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps are checkboxes for tracking.

Outside the ShareCraft repository. Tasks 1 to 3 commit to the GridCraft, WordCraft and PdfCraft forks, on a local branch sharecraft-followups made from each fork's sharecraft branch. Nothing is pushed. Moving sharecraft forward and pushing the forks waits for the owner's go-ahead, as does merging this ShareCraft branch.

Goal: before anyone else uses the editors, (1) the editors' own New, Open and Close can no longer put a different document into the ShareCraft frame, (2) WordCraft starts on a blank page when ShareCraft hosts it, and (3) the SolidCraft build is no longer 153 MB.

Architecture: each craft-web-host editor (GridCraft, WordCraft, PdfCraft) gains a files locked state, switched on in its web build whenever the host bridge is present. While it is on, every way a person can create, open, close or replace a document is turned off, but the host's own path (the bridge's open and save, and execute from the page) keeps working. SolidCraft already does this under ?embed=editor. WordCraft, when hosted, skips its start screen, so ShareCraft drops its blank-then-Escape stopgap. ShareCraft's build tool turns release debug information off for every editor build.

Tech stack: unchanged. Rust in the forks (egui), JavaScript in web/ with node tests, Rust in xtask.

Spec: editors.html section 07 (File menus) and 02 (SolidCraft size); the plan-3 ledger's ruling on WordCraft's blank start. Owner's decisions of 10 November 2026: lock files whenever hosted (no address option); turn debug information off in ShareCraft's build tool, not in the SolidCraft fork; WordCraft's blank start is done now, while WordCraft is being rebuilt anyway.

What this plan does not cover

  • Pushing the forks or moving their sharecraft branches: owner's go-ahead.
  • Path remapping in editor builds (--remap-path-prefix): needed only before a build is published. It changes RUSTFLAGS and so throws away every build cache; left for the publishing work.
  • Serving the editors compressed, a true view-only mode, WordCraft CJK fonts, the editors saving while their tab is hidden: unchanged, still recorded in editors.html.
  • The other items in the plan-3 ledger's "not checked" lists, except where Task 5 happens to cover them.

Global constraints

  • Fork changes stay small and self-contained, in the fork's own style and with its own tests (each fork has an AGENTS.md or CLAUDE.md; follow it). No ShareCraft names in fork code: the state is "hosted", not "ShareCraft".
  • Locking applies only when the host bridge is present. A fork opened on its own (no ?host=parent) behaves exactly as before.
  • Locked means the person's path is refused quietly or with the editor's usual "not available" handling. No new dialogs. Save, Save As (as a download), Print and Export stay.
  • Builds use the personal cargo override rule from BUILDING.html section 13: build editors only through cargo xtask editors build, never trunk in the fork checkout.
  • Never print .env, database addresses or passwords.

Review focus

  1. The host's own open must still work while locked, in every fork: a lock placed on the shared file.open command would break opening the stored file. Each fork task has a test that the host path opens a document while locked.
  2. Keyboard shortcuts and keytips reach commands without the menu: hiding a menu item is not enough. Each fork task tests Ctrl+N, Ctrl+O and Ctrl+W while locked.
  3. A dropped file and a dropped picture: GridCraft and PdfCraft ignore all drops while locked; WordCraft still inserts dropped pictures (they do not replace the document) but opens no dropped document.
  4. WordCraft hosted with stored content: the host's open must replace the untouched blank document, not open beside it as Document2.
  5. Unhosted behaviour unchanged: each fork task has a test that New and Open still work with the lock off.
