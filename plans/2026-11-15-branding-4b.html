Plan 4B, branding: fonts, copying, templates, limits and tab icons: implementation plan

ShareCraft · Stage 2, platform track · Written 15 November 2026

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development or superpowers:executing-plans. Steps are checkboxes.

Goal: plan 4B completes SC-25. It adds:

  • font packages, kept in the brand centre and in sites;
  • copying a look from another site;
  • looks inside site templates and template packages, and applying a look to many sites at once;
  • organisation limits on what site owners may choose;
  • a browser-tab icon for each site;
  • a mega menu style for horizontal navigation.

Architecture: it builds on plan 4A (merged, 6839afc):

  • Records: new fields go on the existing records, org/brand.json and the look and themes fields of site records. Each new field has a default and is left out of the file when it holds that default, so existing records keep their exact bytes.
  • Fonts: font files are snapshots, like brand images. They are pinned in brand_refs, served from a signed-in route, and loaded by pages through the FontFace JavaScript API. That needs no change to the Content Security Policy, because fonts come from the same origin.
  • Templates: templates carry a look. It refers only to brand-centre images and fonts, by their ids, so a template holds no files.
  • Limits: limits are one policy in the brand centre. One server check enforces it on every path that sets a site's look.

Tech stack: the existing workspace and the pages in web/, including the UX-round modules: look-studio.js, brand-centre.js, new-site-wizard.js, admin-shell.js, menu.js and toast.js. No new dependency.

Spec: scope.html:

  • SC-25: fonts; site-level branding and copying; provisioning and API; the brand centre limits; reach (the tab icon);
  • D40, the 4B list;
  • acceptance test A18 (the parts left after 4A).

Proposals in this plan for the owner to check

These are the choices the plan makes. Each is cheap to change before the build starts.

  1. Font files come from asset libraries, like images.
    • Accepted: woff2, woff, ttf and otf, at most 2 MiB each, judged by their content.
    • Whoever adds a font confirms that the organisation holds its licence. The record notes who confirmed it, and when.
    • Fonts are never loaded from outside the installation.
  2. A font package pairs a display font with a content font and maps them to four text roles: title, heading, body and interactive. Every role always falls back to the system fonts.
    • Two built-in packages: System (today's look) and Classic, which uses system serif headings and needs no files.
  3. Limits apply to site owners only. Administrators and brand managers may always choose anything.
    • The limits: hide the built-in themes; allow custom colours; allow site-only themes; allow images from the site's own libraries; allow site-only font packages.
    • Every limit starts off, so nothing changes until an administrator sets one.
    • Looks that already exist keep working. The limits apply to the next change.
  4. Copying a look needs view access on the site it comes from and manage_site on the site it goes to. It copies the look itself; site-only themes and font packages are copied only when asked.
  5. Templates carry a look.
    • Saving a template from a site keeps its look, but drops images that came from the site's own libraries, and says which.
    • Importing a package drops references to brand-centre images or fonts that this organisation doesn't have, and lists them.
  6. Applying a look to many sites at once is for administrators only.
    • One request covers at most 200 sites. Each site gets its own commit and its own history entry, and the answer reports a result per site.
    • Limits don't apply, because an administrator is acting.
  7. The tab icon:
    • A site's look may name an icon image. Without one, the thumbnail is used. Without either, the organisation's default icon from the brand centre is used, and failing that, ShareCraft's own icon.
    • Pages outside any site use the organisation's icon.
  8. Mega menu: horizontal navigation can show each top-level link's children as a full-width panel, in columns, instead of a dropdown list. Audiences still decide who sees each link.

Not in this plan

  • Branded notification emails and public portals: those features don't exist yet (SC-13, SC-18), so each will use its site's look when it is built.
  • A branded sign-in page.
  • Variable-font axis controls.
  • Fonts inside the editors, whose own pages stay untouched.
  • Deferred minor points from plan 4A, unless a task here touches the same code.

Global constraints

  • Font files:
    • The type is judged by content:
      • woff2 starts with wOF2;
      • woff with wOFF;
      • ttf with 00 01 00 00 or true;
      • otf with OTTO.
      Anything else answers 422 not_a_font.
    • Size: at most 2 MiB (413 font_too_large).
    • The content must be available (D37).
    • FontRef = {sha256, media_type (font/woff2 | font/woff | font/ttf | font/otf), bytes, name, from_doc, licence: {confirmed_by, confirmed_at}}.
    • The brand centre holds at most 30 font files.
  • Serving fonts: GET /api/brand/fonts/{sha256}.
    • Signed in only.
    • 404 unless brand_refs names the content; 423 held if it is not available.
    • Headers: the recorded media type, X-Content-Type-Options: nosniff, Content-Security-Policy: sandbox; default-src 'none', Cache-Control: private, max-age=31536000, immutable, and Cross-Origin-Resource-Policy: same-origin.
  • A font package:
    • Shape: {id, name (1–60), display?: FontRef, content?: FontRef, roles: {title, heading, body, interactive}}.
    • Each role is one of display, content, system or system-serif, and must not name a font the package lacks.
    • Built-in packages:
      • builtin:system: every role system.
      • builtin:classic: title and heading system-serif; body and interactive system.
    • Limits: at most 20 packages in the brand centre and 10 site-only packages per site.
  • Family names on the page are generated, never taken from user text: sc-<first 12 hex characters of the sha256>.
    • The system stacks are fixed strings in look.js. System: ui-sans-serif, system-ui, 'Segoe UI', sans-serif. System serif: ui-serif, Georgia, 'Times New Roman', serif.
    • CSS variables --font-title, --font-heading, --font-body and --font-interactive are set through setProperty, and their values are re-checked against a fixed pattern.
    • The account bar, the never-themed list from 4A, code and monospace text keep the system fonts.
  • Look additions:
    • fonts?: {package copy, from: "builtin:<id>" | "org:<id>" | "site:<id>"};
    • icon?: ImageRef, which must be png or svg, square within 10 %, at least 32 px for png, and at most 256 KiB;
    • navigation gains menu: cascading | mega (default cascading); mega applies to horizontal navigation only.
  • OrgBrand additions:
    • fonts: [{id, font: FontRef}];
    • font_packages: [...];
    • default_icon?: brand image id (kind icon);
    • policy: {hide_builtin_themes: false, custom_colours: true, site_themes: true, site_images: true, site_fonts: true}.
  • SiteRecord additions: font_packages: [...], left out of the file when empty.
  • The policy check: policy_problems(look, policy, site_themes, actor) -> Vec<Problem>.
    • It runs on these paths:
      • PUT look;
      • copy;
      • rollback;
      • creating site themes and site font packages;
      • creating a site from a template, when the creator is not an administrator.
    • Administrators and brand managers are never limited.
    • A refusal answers 409 not_allowed {"problems":[...]}, listing each problem in words, for example "custom colours are turned off for site owners".
    • A look already stored is never changed by a policy change.
  • Copying: POST /api/sites/{id}/look/copy {from: site id, themes?: bool, fonts?: bool}.
    • Needs manage_site on the target and view on the source.
    • Images and fonts are pinned to the target as snapshots, in one commit.
    • The change is recorded as site.look_changed with copied_from.
    • An archived target answers 403 archived.
  • Templates: TemplateBody gains look?: TemplateLook.
    • TemplateLook is a look whose images and fonts are references: {brand_image: id} or {brand_font: id}.
    • Saving from a site turns pinned snapshots that match a brand-centre entry into references, and drops the rest. The answer lists them as dropped: [{slot, name}].
    • Creating a site from a template resolves the references, pins them and writes the look in the site's first commit. Unresolved references are dropped and reported in the create answer.
    • Importing a package keeps unresolved references out, and reports them.
  • Applying to many sites: POST /api/admin/looks/apply {sites: [id] (1–200), source: {look} | {from_site} | {template}}.
    • Administrators only.
    • Processed one site at a time, each with its own commit and history entry.
    • The answer is {results: [{site, ok, error?}]}.
    • Archived sites are skipped with archived.
  • Effective look additions (GET /api/sites/{id}/look):
    • fonts: {title, heading, body, interactive}, each {family, url?}, where url is /api/brand/fonts/{sha256};
    • icon_url;
    • navigation_menu.
    The hub rule from 4A also covers fonts: a site in a hub takes the hub's fonts as well as its theme.
  • Organisation brand route: GET /api/brand adds fonts, font packages, the policy and default_icon_url.
    • PUT /api/brand/policy: administrators only.
    • Font routes: POST/DELETE /api/brand/fonts[/{id}] and POST/PATCH/DELETE /api/brand/font-packages[/{id}], for brand managers and administrators.
    • Site font packages: POST/PATCH/DELETE /api/sites/{id}/font-packages[/{id}], needing manage_site and the policy.
  • Events:
    • brand.font_changed;
    • brand.font_package_changed;
    • brand.policy_changed (before and after);
    • site.look_changed with copied_from or applied_by_admin;
    • site.font_package_changed.
  • Errors (each with a plain-English message in common.js):
    • not_a_font 422
    • font_too_large 413
    • licence_not_confirmed 422
    • invalid_font_package 422 {"reason"}
    • not_allowed 409 {"problems"}
    • not_an_icon 422
    • too_many 409
    • name_taken 409
  • Pinning: fonts use brand_refs exactly as images do. The owner is org or a site id, written in the same transaction with the blob locked FOR SHARE, and reconcile rebuilds it from Git. A template's references pin nothing until a site is created from it.
  • Upgrade: no migration is expected, because the new fields live in the existing jsonb columns. If a task finds it needs one, it adds 0016_brand_fonts.sql, and BUILDING says so. Existing records keep their exact bytes.

Review focus

  1. A font file can never run code or inject style. Covered by Task 1 (font_sniffing) and Task 2 (font_inputs_never_run):
    • an HTML or SVG file renamed .woff2;
    • a font name holding "; } body { display:none;
    • a package name with markup;
    • a --font-* value that is not generated.
    Each is refused or shown as text, and the page sets only generated family names.
  2. The limits hold on every path that sets a look: PUT, copy, rollback, site themes and font packages, template create by a non-administrator, and the bulk apply bypass for administrators only. Covered by Task 2, policy_holds_on_every_path.
  3. Fonts are pinned and released exactly like images: when the source file is deleted and its bin emptied, a package is deleted while a look uses its fonts, a look is copied, a site is purged, a template-created site is made, or reconcile runs. Covered by Task 2, fonts_pinned_until_unreferenced, and Task 3, template_sites_pin_their_fonts.
  4. Templates never smuggle files or leak site-only content into other sites: saving from a site with site-library images; importing a package from another organisation with unknown ids; a template made by an administrator used by a site owner under limits. Covered by Task 3, templates_carry_only_brand_centre_references.
  5. Mega menus stay accessible and respect audiences: keyboard (disclosure pattern, Escape, Tab out), screen-reader names, 375 px (falls back to the Menu drawer), and audience-hidden children never sent to people outside the audience. Covered by Task 4, mega_menu_keyboard_and_audiences.
